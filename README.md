# 數獨小學堂

可愛風格的 9×9 數獨小遊戲。支援單機解題，以及可選的線上觀戰與房間留言；零外部套件、零外部資源，打開瀏覽器就能玩。

---

## 一、遊戲企劃摘要

| 項目 | 內容 |
| --- | --- |
| 一句話賣點 | 有耐心陪你想的可愛數獨：每一題都保證只有一組答案，卡住時提示會告訴你「為什麼」。 |
| 目標玩家 | 想在平板／手機上放鬆動腦的人，含完全沒玩過數獨的新手。 |
| 平台 | 響應式網頁（手機／平板／桌機，直向與橫向皆可），觸控優先，同時支援滑鼠與鍵盤。 |
| 一局時間 | 新手入門 3–8 分鐘、簡單 3–8 分鐘、普通 8–15 分鐘、困難 15–30 分鐘、專家 30 分鐘以上。 |
| 人數／模式 | 單人解題；可選擇開啟觀戰房，主持人解題、觀戰者只能觀看盤面、填共享格子留言與使用聊天室。沒有 AI 對手。 |
| 勝利條件 | 81 格全部填滿，且每一列、每一行、每一宮的 1–9 各出現一次。 |
| 失敗條件 | 無。填錯不會結束遊戲，只累計「填錯次數」並可隨時復原。 |
| 帳號 | 不需要。設定、進度與最佳紀錄都存在這台裝置的 localStorage。 |

### 核心遊戲循環

1. 玩家看到 9×9 盤面、上方的時間／剩餘／提示／填錯四個數字，以及下方的工具列與數字盤。
2. 點一個空格 → 空格被框起來，同列行宮淡淡打亮，相同數字一起變色。
3. 按 1–9（觸控數字盤或鍵盤）→ 數字填入，畫面下方用一句話回饋這次動作的結果。
4. 剩餘數量減一、數字盤上該數字的剩餘量減一；填錯會標紅並說明可以怎麼修正。
5. 回到第 2 步，直到剩餘為 0 → 進入結算畫面（時間、提示、填錯、種子、最佳紀錄、累計完成）。

### 所有核心操作

| 操作 | 觸控 | 鍵盤 |
| --- | --- | --- |
| 選格子 | 點格子 | 方向鍵 |
| 填入數字 | 數字盤 1–9 | `1`–`9` |
| 取消填入 | 再按一次同一個數字 | 同左 |
| 筆記模式 | 「筆記」按鈕 | `N` |
| 清除 | 「清除」按鈕 | `Backspace` / `Delete` / `0` |
| 復原 / 重做 | 「復原」/「重做」 | `Z` / `Y` |
| 提示 | 「提示」按鈕 | `H` |
| 暫停 | 「暫停」按鈕 | `Esc` |
| 設定 | 右上角 ⚙ | `Esc` 關閉彈窗 |

觀戰時點任一格右上角的小三角形即可查看格子留言；觀戰者每次送出最多 10 個字，就會像聊天室一樣新增一則歷史留言，玩家與其他觀戰者都會即時看到。觀戰者不能填數字、使用遊戲提示或改動主持人的盤面。

### 難度設計（不是只有名稱不同）

難度同時由「所需解題技巧」與「提示數上限」兩件事決定，出題時會**實際用人類解法解一次**來驗證：

| 難度 | 需要的技巧（分級器實測） | 提示數 | 挖洞時的技巧上限 |
| --- | --- | --- | --- |
| 新手入門 | 大多數步驟是整列／整行／整宮只剩一格 | 48–55 | 唯一候選數 |
| 簡單 | 只需要「唯一候選數」（某格只剩一個數字可填） | 40–45 | 唯一候選數 |
| 普通 | 一定會用到「隱藏唯一數」（某數字在該列／行／宮只剩一格能放） | 32–36 | 隱藏唯一數 |
| 困難 | 一定會用到區塊摒除／裸對，部分題目需要裸三、隱藏對或 X-Wing | 26–30 | 進階技巧 |
| 專家 | 基本與進階技巧都推不完，需要假設與試誤 | 21–25 | 不設限 |

單元測試會對每個難度的多組種子逐題驗證：簡單「只用唯一候選數就解得完」、普通「只用唯一候選數解不完但加上隱藏唯一數就可以」、困難「兩種唯一數解不完但進階技巧可以」、專家「進階技巧也解不完」。

### 最小規則例子（已轉成測試）

- **正常流程**：空格 `R1C3` 的正解是 `4` → `setValue(state, 2, 4)` → `{ ok: true, wrong: false }`，剩餘 −1。
- **非法操作**：`R1C1` 是題目給的數字 → `setValue(state, 0, 5)` → `{ ok: false, code: 'given' }`，盤面完全不變。
- **結算流程**：最後一格填對 → `{ ok: true, won: true }` → `status` 變成 `won`，之後任何填入都回 `{ ok:false, code:'finished' }`。

### 明確不做的範圍

AI 對手、帳號系統、雲端排行榜、每日挑戰、成就系統、變體數獨（對角線／殺手）、直式輸入外的手寫辨識。

## 二、怎麼啟動

### 方法 A：按批次檔（最簡單）

在檔案總管點兩下 **`啟動遊戲.bat`**。會啟動伺服器並自動開瀏覽器到 `http://localhost:3010`。
同一個 Wi-Fi 下的平板，用主控台印出的區網網址（例如 `http://192.168.x.x:3010`）就能一起玩。

### 方法 B：命令列

```bash
cd "C:\Eric\AI Agent\sudoku"
npm start          # 等同 node server.js，預設 port 3010
```

### 方法 C：完全不用伺服器

`public/index.html` 沒有任何外部相依，直接用瀏覽器打開這個檔案也能玩（`file://` 亦可）。
`public/` 整個目錄就是可以直接上線的靜態網站，`.github/workflows/deploy-pages.yml` 會把它推到 GitHub Pages。

### 指令

```bash
npm test                       # 規則、流程、介面結構、線上邏輯、部署設定、編碼的單元檢查（72 組）
npm run test:browser           # 用無頭 Chrome 實際跑一遍：RWD、完整一局、設定、持久化、server URL
npm run test:online            # 實際 HTTP／SSE：多位觀戰者同步盤面、格子留言、聊天室與關房
npm run verify                 # 上面兩個一起跑
npm start                      # 啟動靜態伺服器
```

## 三、專案結構

```
sudoku/
├─ server.js                 靜態檔案伺服器 + 線上觀戰／格子留言／聊天室 API（零外部套件）
├─ 啟動遊戲.bat              Windows 一鍵啟動
├─ package.json / render.yaml / .env.example / .github/workflows/
├─ public/
│  ├─ index.html             所有畫面的結構（單頁多 section）
│  ├─ css/style.css          可愛主題 + 全部 RWD 斷點
│  └─ js/
│     ├─ config.js           唯一的 server URL 設定入口（部署時注入，預設單機）
│     ├─ rng.js              可注入的種子亂數（mulberry32 + FNV-1a）
│     ├─ sudoku.js           規則核心：合法性、解題、唯一解、人類解法分級、挖洞出題
│     ├─ game.js             一局的狀態機：填入／筆記／清除／復原／提示／勝利／存讀檔
│     ├─ storage.js          localStorage 讀寫（設定、進度、紀錄）
│     ├─ svgui.js            立體 SVG 按鈕、LOGO、獎盃、背景裝飾
│     ├─ audio.js            Web Audio 即時合成的音樂與音效
│     └─ app.js              畫面切換、盤面繪製、輸入處理、線上觀戰與設定彈窗
├─ tests/verify.js           規則、狀態與伺服器邏輯單元檢查
├─ scripts/browser-check.js  無頭瀏覽器 RWD／流程檢查
├─ scripts/online-check.js   真實 HTTP／SSE 線上端到端檢查
└─ scripts/inject-server-url.js  部署時把 GAME_SERVER_URL 寫進 config.js
```

### 分層原則

`sudoku.js` 與 `game.js` **完全不碰 DOM、不碰音訊、不碰儲存**，所以同一份程式可以直接在 Node 的 `vm` 沙箱裡跑完一整局。UI（`app.js`）只做三件事：把狀態畫出來、把輸入轉成動作、把動作結果的 `message` 顯示給玩家。

## 四、種子出題

- 出題畫面可以輸入種子，或按「🎲 換一組」隨機產生。
- 種子字元集刻意拿掉容易看錯的 `0 O 1 I`，方便口頭或紙筆傳遞（所以輸入 `RWD1` 會被正規化成 `RWD`）。
- **同一個種子 + 同一個難度 = 同一題**，可以跟朋友比同一題誰快。
- 留白代表隨機出題，實際使用的種子會顯示在遊戲畫面與結算畫面上。

## 五、RWD 與設定

- 檢查點：手機窄版 360×640、手機直向 390×844、手機橫向 844×390、小手機橫向 667×375、平板直向 768×1024、平板橫向 1024×768、桌機寬版 1440×900。
- **直向**：盤面在上、工具列與數字盤在下（窄版 5 欄、平板直向 9 欄一排）。
- **橫向**：盤面在左、工具列與數字盤收成右側 3×3 直欄；矮橫向時標題列與數據列會併成同一排，把高度讓給盤面。
- **窄版**：難度卡改成單欄橫式、標題列的技巧標籤與種子標籤收起（結算畫面仍看得到）。
- 右上角 ⚙ 在**每一個畫面**都在同一個位置（`position:fixed` + 安全區內距，至少 48×48），按下開啟 Modal 彈窗：遮罩、`role="dialog"`、`aria-modal`、Tab 焦點鎖定、Escape／手機返回鍵關閉、關閉後焦點歸位。
- 設定內容：背景音樂開關與音量、遊戲音效開關與音量（兩者完全獨立）、觸控震動、動畫效果（減少動態）、自動整理筆記、即時標示填錯、高亮相同數字、高亮同列行宮、數字盤顯示剩餘、恢復預設。全部立即套用並寫入 localStorage。

## 六、資產與授權

| 類型 | 目前做法 | 需要替換嗎 |
| --- | --- | --- |
| 圖形 | LOGO、獎盃、按鈕立體外觀、背景裝飾都是這個專案自己寫的 inline SVG（`svgui.js`），沒有引用任何第三方圖檔 | 不需要，但若要換成正式美術，替換 `svgui.js` 的 `logo()` / `trophy()` 即可 |
| 圖示 | 少數 UI 圖示（⚙ ✏️ 💡 ⌫ ↶ ↷ ⏸ 🔁 🏅 📖 🎲）使用系統字型的字元，非核心視覺 | 想完全掌控外觀時可換成自製 SVG |
| 字型 | 只指定系統字型（圓體 → PingFang → 微軟正黑體 → Noto Sans TC → sans-serif），不下載任何字型檔 | 想固定所有裝置的字型時需自備授權字型 |
| 音效／音樂 | 全部由 `audio.js` 用 Web Audio 即時合成，**沒有任何音檔**，因此沒有授權問題 | 想要正式配樂／音效時替換 `audio.js` 的 `SFX` 表與 `MEL`／`BASS` 旋律表，對外介面（`Sound.play` / `startBgm` / `stopBgm`）保持不變即可 |

沒有任何外部網址、CDN、追蹤程式或秘密金鑰。

## 七、Git、server URL 與部署

### 架構：前端在 GitHub Pages，伺服器在 Render

```
玩家 ──▶ GitHub Pages（靜態前端 public/）
              │  只有在有設定 server URL 時才會連線
              ▼
         Render（server.js，提供 /health、房間、觀戰、格子留言與聊天室 API）
```

沒有設定 server URL 時，遊戲會完整以單機模式運作，成績與進度存在玩家自己的裝置上；設定 server URL 後才會啟用線上大廳、觀戰、共享格子留言與聊天室。
線上房間資料只存在伺服器記憶體，房間關閉或服務重啟後就會消失。
在線上模式從主選單開始新題目會直接開房；結算後按「同難度再一題」會沿用原房號、邀請連結與觀戰者，只廣播新的盤面。

### server URL 怎麼參數化

唯一的設定入口是 **`public/js/config.js`**，其他檔案一律不准出現寫死的網址（`npm test` 會擋）。
它解析的優先序是：

1. 網址參數 `?server=...`（臨時覆蓋，測試 staging 很好用）
2. 部署時注入的值（`scripts/inject-server-url.js` 從環境變數 `GAME_SERVER_URL` 寫進去）
3. 都沒有 → 單機模式

值一定要是 http/https 的絕對網址。格式不對、或 https 頁面想連 http 伺服器（瀏覽器會擋混合內容），
都會被判定為設定錯誤並退回單機模式，**不會**靜默回退到 localhost 或任何寫死的網域。

版控裡的 `config.js` 永遠是空字串，正式網址只在部署當下注入，不進 Git。

```bash
# 本機測試（明確允許本機網址）
node scripts/inject-server-url.js --allow-local http://localhost:3010

# 從環境變數注入（CI 用的就是這個）
GAME_SERVER_URL=https://xxx.onrender.com node scripts/inject-server-url.js

# 還原成單機模式
node scripts/inject-server-url.js --clear
```

### 步驟 A：伺服器部到 Render

1. Render → New → Web Service → 連到這個 GitHub repo，它會讀 `render.yaml`。
2. 設定值（`render.yaml` 已寫好）：Build `npm install`、Start `node server.js`、Health Check `/health`。
   `PORT` 由 Render 自動注入，`server.js` 直接讀 `process.env.PORT`。
3. 在 Render 的 Environment 加上 `GAME_ALLOWED_ORIGIN`，值填 GitHub Pages 的網址
   （例如 `https://pjh-eric.github.io`）。不設定就是不限制來源。
4. 部署完成後打一下 `https://<你的服務>.onrender.com/health`，應該回
   `{"status":"ok","game":"sudoku",...}`。

**免費方案的實際限制**（不要當成永久保證）：閒置約 15 分鐘後服務會休眠，下一個請求要等冷啟動
（通常十幾秒到一分鐘）；檔案系統是暫時的，重新部署或重啟就會清空；每月有執行時數與頻寬額度。
所以前端的健康檢查逾時放到 8 秒，而且連不上時只是顯示「連不上」，不會擋住遊戲。
線上房間資料只存在伺服器記憶體中，重啟或重新部署會清空；單機成績與進度仍只存在玩家裝置。

### 步驟 B：前端部到 GitHub Pages

1. GitHub → Settings → Pages → Source 選 **GitHub Actions**。
2. （選用）Settings → Secrets and variables → Actions → **Variables** → New variable：
   名稱 `GAME_SERVER_URL`，值填 Render 給的網址（`https://xxx.onrender.com`）。
   不設定就是單機模式，網站照樣完整可玩。
3. push 到 `main` 就會觸發 `.github/workflows/deploy-pages.yml`：注入 server URL → 上傳 `public/` → 發布。
4. 網址會是 `https://<帳號>.github.io/sudoku/`。所有資源都用相對路徑，放在子路徑底下不會壞；
   `public/.nojekyll` 確保 Jekyll 不會吃掉檔案。

### 環境變數一覽

| 變數 | 用在哪 | 說明 |
|---|---|---|
| `GAME_SERVER_URL` | GitHub Actions variable | 前端要連的伺服器位址；部署時注入 `config.js`。留空＝單機 |
| `GAME_ALLOWED_ORIGIN` | Render 環境變數 | 允許跨來源存取 `/health` 的前端網址，逗號分隔；`*` 為不限制 |
| `PORT` / `HOST` | Render 環境變數 | 監聽的埠與介面；Render 會自動注入 `PORT` |

範例值放在 `.env.example`（`.env` 已被 `.gitignore` 排除，不要提交任何真實網址或密鑰）。

### 分支與回滾

`main` 是唯一的部署分支：push 到 `main` 會同時觸發 Pages 發布與 Render 部署。
每次部署都對應一個 commit，要回滾就 `git revert` 後再 push，或在 Render 的 Deploys 頁面
直接 rollback 到上一個成功的部署。Pages 的部署紀錄在 Actions 頁面可以重跑。

上線前先在本機跑過 `npm run verify`，這一份跟 CI 跑的是同一套檢查。

## 八、已知的取捨

- **9×9 格線的單格大小**：在極矮的橫向手機（例如 667×375）每格約 31–32px，低於一般按鈕建議的 44px。這是固定格線的必然結果，常見數獨 App 也是同一個量級；直向時每格會回到 35px 以上。小螢幕建議直握。
- **窄於 400px 的螢幕**：遊戲畫面的標題列不顯示種子與技巧標籤，改在結算畫面顯示，換取更大的盤面。
- **復原歷史不進存檔**：離開再回來會保留盤面、筆記、時間與計數，但復原／重做的歷史會清空。
- **專家難度**：依定義就是基本技巧推不完、需要假設試誤的題目，卡住時請善用提示（提示不限次數，只會記在結算畫面）。
